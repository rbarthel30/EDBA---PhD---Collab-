### 2. Git vocabulary
Quick reference of the terms we covered:

- **Commit** — a saved snapshot of your project at a point in time, with a short message describing what changed. Commits are local until you push them. Think of each commit as a labeled checkpoint you can return to later.
- **Push** — uploads your local commits to the shared GitHub repository so the other person can see them.
- **Pull** — downloads the latest commits from GitHub into your local copy so you're working from the newest version. Always pull before starting new work to avoid conflicts.
- **Worktree** — an additional working copy of the repo on your machine, linked to the same project history but pointed at a different branch. Lets Claude (or you) work on an isolated experimental version without disturbing your main copy.

### 3. AI-assisted literature review
- Demonstrated using Claude to pull a curated reading list on a topic (capital-market and real effects of FDA warning letters).
- **Key caveat: verify every citation.** LLMs can hallucinate plausible-sounding but nonexistent papers, wrong authors, wrong journals, or wrong years. Treat AI output as a starting pointer, not a verified reference — always confirm against Google Scholar, SSRN, or the journal's own page before quoting in a manuscript.

### 4. Optimizing Claude Code for academic research
- Reviewed how Claude Code can be tuned for empirical econ workflows beyond a generic coding assistant.
- **Skills** — packaged instructions Claude loads when triggered (e.g., audit a regression script, summarize a paper, scaffold a research project).
- **Hooks** — automated rules in `settings.json` that fire on events (e.g., enforce a coding style, log every Bash command, block writes outside the project folder).
- **Sub-agents** — specialized reviewers (econometric code reviewer, regression-spec auditor, results replicator) that can be invoked to vet work before it goes into the paper.

### 5. Sandbox for Armando's work laptop
- Armando's work laptop has IT restrictions that limit what Claude can do autonomously (file writes, package installs, etc.).
- Introduced **sandbox mode** as the workaround: Claude runs in an isolated environment where it has freedom to read, write, and execute without touching the host machine's protected files. Lets Armando get the productivity benefits of agentic Claude without violating his employer's IT policy.
